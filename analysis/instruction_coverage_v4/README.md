## 数値の版を混同しない

schema 4 の上位 `C` は全要件が解決したときの `fulfilled / 全要件数`。
保留があれば null。上位 `S` / `delta_e` / `quality_score` は常に null。
旧 C は語集合・cascade 由来の hits 比率で、旧 `quality_score=5−4ΔE` は
ΔE の線形変換にすぎない。旧値は `legacy_metrics`、構造ゲートは `binding=false`。
旧 C の AUC・相関や HA48 の人手評点との関係を、現行 C の精度として読まない。

追加価値の不採用判断は、評価した旧実装と、明示された必須情報の記載点検という用途に
限定する。UGH の全理論・全用途や、将来の修正版を一括して否定する結論にはしない。
JSON・引用・モデル・文脈の検証と障害時非 accept は運用上のガードとして区別する。

## ネットワーク不要の検算

Python 3.10 以降の標準ライブラリだけを使う。リポジトリの任意のカレントディレクトリから:

```console
python analysis/instruction_coverage_v4/verify_artifacts.py
```

スクリプトを絶対パスで実行しても、自身の隣の `manifest.json` から解決する。
別の展開先は `--artifact-root <bundle-directory>` で指定できる。
既定では stdout に結果を出し、コミット済みファイルを変更しない。
`--output <new-file.json>` は未使用の出力名だけを受け付ける。

検算は全保存ファイルの SHA256、Gold・入力・要件番号、1176件のモデル原応答の
JSON 投影と実在引用、モデル名・request ID、要件集約、旧判定との対応、
盲検レビューの対応と固定順序、保存 JUnit の件数を検査する。
API・環境変数・認証情報にアクセスせず、製品・モデル本体も import しない。
保存メタデータと本文の整合検査であり、プロバイダーが署名した実行証明ではない。
現在のコードの実行テストや独立した意味再採点とも異なる。

任意で評価当時の checkout を `--evaluated-source <checkout-of-3e0a289>` に渡すと、
固定した76ファイルも照合する。後続修正を含む HEAD に対しては不一致が予想される。
現行 HEAD のテストは別の回帰記録で確認する。
後続修正後の全体回帰は `regression/pr-head.xml` の1,053件成功・スキップ0。
`--current-source <current-checkout>` はその回帰で検査した実行・テストファイルの
SHA256も照合する。これは後続HEADの回帰証拠で、新しい未見モデル評価ではない。

`regression/baseline886.xml` と `evaluated965.xml` は元の JUnit をバイト保存したもの。
どちらも失敗・エラー・スキップ0。nodeid 比較は追加92・除去/置換13で純増79。

収集スキップで、実際には824実行から62件を実行して886になった。

## 保存と除外

`evidence/` は合成入力・Gold・原応答を含む評価行、`summaries/` は当時の集計、
`provenance/` は固定条件と盲検資料、`regression/` は当時の JUnit。
元成果物とコピーの SHA256 は `manifest.json` に記録した。
原応答・Gold・集計・XML はバイト単位で保存。2つのレビュー manifest だけは
入力・出力フィールド（1番は `input_file` / `output_file`、2番は `input` / `output`）の
個人絶対パスを相対ファイル名へ置換した派生で、
元 SHA と変更フィールドも明記している。datafreeze の旧ハッシュ参照には元 SHA を使い、
コミット済み派生自体は別 SHA で検証する。元ファイルはローカル保存済み。

全モデル原応答 ZIP、重複した全ソース、秘密情報・env、モデル重み・cache、venv、
個人パスを含む環境 lock / テストログ、SQLite は含めていない。
この最小構成は保存証拠の再集計を再現する。元の実 API 通信や製品実行環境全体の
再現パッケージではない。
